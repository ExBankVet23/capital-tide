Methodology & data schema — how this desk is scored

This board is a proxy system, not a literal flow tracker — no single feed reports "$X moved into commodities today." It infers where new liquidity is being absorbed by scoring three layers daily: source (liquidity creation), transmission (funding/financial conditions), and destination (cross-asset absorption & breadth), then reading the handoff between them.

Composite regime weighting

Regime = 0.35·Liquidity + 0.30·Funding + 0.20·Credit + 0.15·DestinationBreadth, each layer −3…+3 via rolling z-scores. Tighter-is-bad series (DXY, real yields, spreads, VIX) are sign-flipped before blending.

Bucket score

BucketScore = 0.40·z(level) + 0.35·z(trend) + 0.25·z(relative strength) — weighted toward level for liquidity/funding series, toward trend & relative strength for asset buckets.

Wiring in live data

The dashboard ships with fetch_data.py, a free-data pipeline: Fed balance sheet/TGA/RRP + yields/spreads/VIX from FRED, equities/credit/commodities/sectors from Stooq, BTC/ETH + self-computed BTC Dominance and Altseason Index from CoinGecko, stablecoin supply from DefiLlama, COT positioning from the CFTC's official API, and perp funding rate/open interest from Binance's public API — all free, no paid tier required. It writes a data.json that this page loads automatically; any series it can't find falls back to synthetic data for that series only. See README_DATA_SETUP.md for the ~10-minute setup.
